# 公开作品列表游标分页接口变更

实施日期：2026-09-21。后端代码、生成结果、迁移和本地 PostgreSQL 验收已完成；未执行生产部署。

## 1. 变更范围

以下两个接口采用相同的分页协议：

| 接口 | 权限 | 作品范围 |
| --- | --- | --- |
| `GET /v1/official/dates/{biz_date}/uploads` | 公开访问；携带有效身份时返回该用户的互动状态 | 指定业务日期的官方公开作品 |
| `GET /v1/review/keywords/{keyword_id}/uploads/all` | 必须登录 | 指定关键词的全部官方公开作品 |

此前接口只返回首批作品，现在可以通过 `next_cursor` 连续读取。两个接口的 URL、现有卡片字段、图片变体、图片 URL 规格、互动计数开关和权限保持原有行为。官方详情、自定义详情及“我的作品”列表不在本次改造范围。

## 2. 请求参数

| 参数 | 类型 | 首次请求 | 后续请求 |
| --- | --- | --- | --- |
| `cursor` | string，可选 | 不传，开启新一轮 | 原样传回上一页的 `next_cursor` |
| `sort` | `latest` / `random`，可选 | 不传使用 `latest` | 不传从游标恢复；显式传入必须一致 |
| `limit` | integer，可选 | 默认 20，范围 1–50 | 相同规则，允许改变批大小 |
| `seed` | double，可选 | random 使用 `[0,1)` 内有限数值，不传由服务端生成 | random 不传从游标恢复；显式传入的合法值必须一致 |
| `include_reaction_counts` | boolean，可选 | 默认 false | 每次请求独立生效，建议一轮保持一致 |

注意事项：

- `cursor` 必须 URL 编码后传输，客户端不解析、不拼装。最大长度为 URL 解码后 2048 字节。
- 不传 cursor 表示新一轮；显式 `cursor=` 是非法游标，不等同于首次请求。
- `latest` 忽略额外携带的正常数值 seed，包括超出随机范围的数值。无法解析的数字、NaN、Infinity 仍由现有请求校验拒绝。
- 无论 latest 还是 random，limit 越界都返回 400，不在 HTTP 层静默截断。
- 刷新随机列表时不传旧 cursor 和 seed；服务端生成新 seed，不保证两次随机顺序必然不同。
- 游标不绑定账号或计数开关。当前请求仍重新鉴权，并根据当前用户补充 `my_reactions`；关键词接口不能凭游标绕过登录。
- 两个接口的 OpenAPI `sort` schema 不再声明固定默认值。首次默认 latest 由应用层处理，避免请求校验器把随机续页自动补成 latest。

日期接口示例：

```text
GET /v1/official/dates/2026-09-21/uploads?sort=random&limit=20
GET /v1/official/dates/2026-09-21/uploads?cursor=<URL编码后的next_cursor>&limit=20
```

关键词接口示例，两个请求均需要现有 Bearer Token：

```text
GET /v1/review/keywords/{keyword_id}/uploads/all?sort=latest&limit=20
GET /v1/review/keywords/{keyword_id}/uploads/all?cursor=<URL编码后的next_cursor>&limit=50
```

## 3. 响应契约

响应仍是顶层对象，不增加 `data` 包装。客户端 Axios 的 `res.data` 是 HTTP 响应体。

```typescript
type PublicUploadsPage = {
  items: PublicWorkUploadCard[]; // 沿用现有卡片结构
  seed: number | null;
  next_cursor: string | null;
  has_more: boolean;
};
```

四个字段都固定输出，OpenAPI 均列为 required：

| 字段 | 行为 |
| --- | --- |
| `items` | 当前页卡片；空结果固定为 `[]` |
| `seed` | latest 为 null；random 为本轮 seed，包括空结果 |
| `next_cursor` | 有下一页时为非空字符串；末页为 null |
| `has_more` | 是否还有下一页，与 `next_cursor` 是否非空一致 |

空 latest 响应：

```json
{"items":[],"seed":null,"next_cursor":null,"has_more":false}
```

空 random 响应示例：

```json
{"items":[],"seed":0.3,"next_cursor":null,"has_more":false}
```

`reaction_counts` 在开关关闭时保持原有省略行为；没有个人互动时 `my_reactions` 保持原有 null 语义。图片仍使用原有 `cover_image.variants.card_4x3` 等结构。

客户端以 `has_more` 和 `next_cursor` 判断续页，不能以本页长度或去重后长度猜测末页。续页失败后重试同一 cursor；静态数据下结果顺序一致。不要将失败游标替换为无 cursor 的首屏并追加到旧列表。

## 4. 错误契约

沿用统一错误体：

```json
{
  "code": "validation",
  "reason": "readmodel.invalid_cursor",
  "message": "invalid cursor",
  "request_id": "当前请求标识"
}
```

| 情况 | HTTP | code | reason |
| --- | --- | --- | --- |
| 空或超长游标、非法编码/JSON、未知版本/字段、缺失必要字段、非法排序键或内部矛盾 | 400 | validation | `readmodel.invalid_cursor` |
| 游标与日期/关键词/scope 不匹配，或显式 sort/合法 seed 不一致 | 400 | validation | `readmodel.cursor_mismatch` |
| limit、sort、随机 seed 等普通参数非法 | 400 | validation | `validation.failed` |
| 日期/关键词不存在 | 404 | 沿用原值 | `readmodel.not_found` |
| 关键词接口没有有效身份 | 401 | 沿用现有鉴权错误 | 沿用原值 |
| 限流或服务异常 | 沿用现状 | 沿用原值 | 沿用原值 |

普通参数错误保留现有 `details` 字段错误结构。客户端应按 `reason` 分类处理，不依赖 message 文案。两个游标错误应提示刷新当前列表，保留已显示内容；其他错误不能转换为空列表成功。

## 5. 排序与数据变化语义

### latest

按 `(published_at DESC, id DESC)` 稳定排序。续页只读取严格小于上一页最后排序键的作品；UUID 解决相同发布时间的排序问题。

### random

沿用已有的 rand_key 环形顺序，并非对作品池重新洗牌：

1. 高段：`rand_key >= seed`，按 `(rand_key ASC, id ASC)`。
2. 低段：`rand_key < seed`，按相同方向读取。
3. 高段不足时补读低段；进入低段后的续页不会返回高段。

每页最多获取 `limit + 1` 条完整有效卡片，多出的一条只用于判断下一页。游标取最后一条实际返回卡片，不取探测卡片。高段恰好剩 20 条、limit=20 且低段仍有记录时，返回的游标仍位于高段；低段探测记录会在下一页正常出现。

所有分页查询重新应用公开可见、业务上下文、路径 scope、软删除和完整封面关联过滤。互动补充保持批量查询，并只处理实际返回的卡片。

### 时间上界及变化

首次请求在日期/关键词检查完成后读取数据库 `clock_timestamp()`，作为该轮 cutoff。后续页始终要求 `published_at <= cutoff_at`，时间保留微秒，浮点排序键保留 float64 往返精度。

这是带时间上界的浏览轮次，不是跨请求数据库快照：

- 静态数据中，每条有效作品恰好遍历一次。
- 发布时间晚于 cutoff 的新增作品在刷新开启新一轮后出现。
- 作品隐藏、删除、封面失效后，后续请求排除它们；已返回画面由客户端刷新或删除事件处理。
- 恢复可见、旧时间回填、长事务晚提交可能进入尚未扫描的区间；位于已经扫描区间的记录需要刷新才能看到。
- `published_at` 默认值 `now()` 使用事务开始时间，所以不能将 cutoff 解释为“首次请求后提交的记录绝不会出现”。
- 随机单页的两段查询使用同一个只读 Repeatable Read 短事务。后续 HTTP 请求取得新的读取视图。
- 游标不设置到期时间，不承载授权，也不保证防篡改快照。修改游标不能改变服务端重新构造的权限及 scope 筛选。

## 6. 后端实现与迁移

增加 `000007_public_upload_pagination` up/down migration：

| 索引 | 键 | 部分索引条件 |
| --- | --- | --- |
| `idx_work_uploads_public_date_rand` | `(biz_date, rand_key, id)` | official_today、visible、未软删除 |
| `idx_work_uploads_public_keyword_rand` | `(official_keyword_id, rand_key, id)` | 相同 |

保留旧随机索引和已有 latest 索引。Repository 使用独立的首屏/续页 SQL，不使用 OFFSET、每页 COUNT 或 CASE 随机排序。

执行计划核对发现，普通封面 JOIN 的相关条件可能使 PostgreSQL 严重低估行数，进而扫描候选集后排序。分页 SQL 因此将封面图片改为相关 LATERAL 单行查找；现有 `(upload_id, image_asset_id)` 唯一约束保证语义不变。内部 LIMIT 1 仅用于该作品的唯一封面查找；页面 LIMIT 仍在封面图片、媒体资产等全部过滤之后，封面失效不会产生提前判定末页的问题。

### 发布

1. 小测试库按现有迁移入口执行 up。
2. 大生产表先逐条、分别执行以下并发建索引语句，不放进事务块，也不作为同一次多语句执行提交。

```sql
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_work_uploads_public_date_rand
ON work_uploads (biz_date, rand_key, id)
WHERE context_type = 'official_today'
  AND visibility_status = 'visible' AND deleted_at IS NULL;
```

```sql
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_work_uploads_public_keyword_rand
ON work_uploads (official_keyword_id, rand_key, id)
WHERE context_type = 'official_today'
  AND visibility_status = 'visible' AND deleted_at IS NULL;
```

3. 查询并核对两个索引的键、谓词、`indisvalid=true` 和 `indisready=true`：

```sql
SELECT c.relname, pg_get_indexdef(i.indexrelid), i.indisvalid, i.indisready
FROM pg_index i JOIN pg_class c ON c.oid = i.indexrelid
WHERE c.relname IN (
  'idx_work_uploads_public_date_rand',
  'idx_work_uploads_public_keyword_rand'
);
```

4. 若同名索引定义不符或无效，停止发布并修复。`IF NOT EXISTS` 本身不会校验索引定义和有效性。
5. 确认预建正确后，通过现有迁移程序执行 up；migration 的 `IF NOT EXISTS` 接纳预建索引。
6. 先发布兼容旧请求的后端，检查两个接口的四字段响应，再发布启用分页的前端。

应用回退时可保留新索引；迁移 down 只删除本次两个索引。新前端遇到旧后端缺少分页字段时应停止续页，保留首批浏览。
